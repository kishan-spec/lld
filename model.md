# Design Pattern Checklist

Whenever you come across a design pattern, ask yourself these questions:

- **What problem does it solve?**
- **What is the structural idea?**
- **When would I actually use it?**


# Design Pattern Mental Models

- Adapter
  - "The interface doesn't match."
  - Convert one interface into another interface.

- Decorator
  - "I want to add behavior."
  - Dynamically wrap an object with additional behavior.

- Facade
  - "This subsystem is too complicated for the client."
  - Provide one simple interface over a complex subsystem.

- Composite
  - "I have a tree structure."
  - Treat individual objects and groups uniformly.

- Proxy
  - "I need a stand-in that controls access."
  - Put something in front of the real object.

- Bridge
  - "I have multiple independent dimensions of variation."
  - Separate those dimensions so they can evolve independently.

- Flyweight
  - "I'm creating tons of similar objects."
  - Share common state to reduce memory usage.
